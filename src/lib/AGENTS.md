# Server Libraries

## Purpose

- Own persistence, provider authentication services, network helpers, usage data, tunnels, updater behavior, MCP integration, and other server-side application services.

## Ownership

- Root database modules such as `localDb.js`, `usageDb.js`, `requestDetailsDb.js`, and `disabledModelsDb.js` own durable local state contracts.
- `db/` owns storage drivers, migrations, repositories, and database lifecycle.
- `oauth/` owns provider authorization, token exchange, refresh, and import services.
- `auth/`, `network/`, `usage/`, `tunnel/`, `updater/`, `mcp/`, and provider-specific folders own their named server domains.

## Local Contracts

- Preserve stored data compatibility and migration order; never discard user data as an incidental fix.
- Keep secrets out of logs, responses, fixtures, and committed files.
- Make writes resilient to partial or concurrent operations using existing repository and transaction patterns.
- Database adapter methods accept positional parameters as arrays; the `better-sqlite3` adapter must spread those values into prepared statement calls.
- File-backed automation snapshots use unique temporary files and Windows-safe replacement; never delete the last valid snapshot before its replacement is durable.
- Preserve provider-connection deduplication by default; use explicit repository options when a caller intentionally supports multiple same-name API-key connections.
- OAuth connection deduplication must not collapse same-email identities when their workspace account IDs or provider usernames differ or exist on only one side.
- Keep environment and data-directory handling centralized rather than hard-coding platform paths.
- Changes to storage shape, credential lifecycle, or externally visible side effects require tests and documentation updates.
- Authentication and rate-limit code may trust `x-9r-real-ip` only through `auth/trustedPeer.js`, which verifies the per-process proof generated by `custom-server.js`.
- Usage history and aggregate responses must expose masked API-key values and masked object keys only; raw keys remain internal to persistence and name lookup.
- Validate outbound proxy URL schemes before exporting them, and HTML-escape provider callback messages before rendering browser result pages.

## Work Guidance

- Use existing repository, normalization, and provider service APIs before reaching directly into storage.
- Keep provider-specific token fields and refresh rules in provider-local services.
- Keep Trae, Windsurf, and Zed definitions inside the protected single-file `oauth/providers.js`; callback exchange may contact only fixed HTTPS API origins, and callback proxies bind loopback and validate state or an RSA-bound credential before persistence.
- Keep browser automation, session scraping, and bulk account import flows inside provider-local OAuth services rather than route handlers or dashboard components.
- Provider bulk import managers should clear provider-specific interstitials, modals, and login gates before deciding a browser session is stuck or needs manual assist.
- Provider automation must use isolated Camoufox sessions; bulk workers run headless and close only the affected worker context after callback capture while retaining redirect-header and navigation-event fallbacks.
- Provider OAuth wrapping may use one visible Camoufox session through a resolved browser-compatible proxy pool; never persist or return the resolved proxy URL or credentials in job state.
- CodeBuddy CN and Global OAuth wrapping preflight pool proxies against the provider HTTPS login endpoint in pool order and launch only with the first reachable proxy; failed transport details and credentials stay server-private.
- Their Auto pool mode aggregates all active browser-compatible pools and retries the visible browser launch with subsequent preflight-valid proxies until one opens or candidates are exhausted.
- Visible Camoufox OAuth sessions use a compact laptop-sized window through Camoufox's native fingerprint-aware `window` option; headless worker sizing remains runtime-managed.
- CodeBuddy Global bulk GSuite jobs resolve one proxy pool at job start and give every account its own Camoufox process; when the pool is smaller than the account count, proxies are reused round-robin instead of failing the job. Runtime proxy URLs never enter persisted or sanitized job state.
- CodeBuddy Global GitHub-register bulk jobs (distinct from bulk-login) enforce one **unique** proxy per account and reject when the resolved pool has fewer unique proxies than requested accounts; GitHub blocks repeat signups from the same exit IP within a short window, so round-robin is unsafe for this flow.
- CodeBuddy Global GitHub-register bulk jobs allocate disposable email addresses via the Privatix temp-mail API and require every account in a batch to land on a distinct Privatix domain; the `PrivatixTempMailClient.allocateUniqueAddresses` helper caps allocation to the currently exposed Privatix domain count and surfaces a `capped` flag so callers can log the shortfall rather than silently repeating a domain.
- GitHub signup credentials (username/password) generated by the register manager live only on the in-memory account object and are scrubbed in `finalizeAccount`; they are never written into sanitized snapshots, saved connections, or persisted job JSON.
- CodeBuddy CN automation follows the recovered enow lifecycle: create the API key, probe credits and gateway state, run best-effort activation, then save credentials with activation and probation metadata; activation uncertainty must not discard otherwise valid credentials.
- CodeBuddy CN 5sim registration must confirm the SMS login surface before buying a number, request OTPs through the visible CodeBuddy UI, and retry after cooldowns without using direct SMS endpoints.
- Keep 5sim client behavior centralized in `oauth/services/fiveSimClient.js`, including token validation, price/stock quote caching, OTP polling, and proxy-dispatched fetches.
- Google automation must evaluate Google OAuth consent before credential inputs and prefer a short, force-enabled native locator click on its approval control; synthetic DOM events are fallback-only because Google may ignore untrusted clicks while leaving the fixed, localized consent footer visible.
- After submitting a Google identifier or password, preserve a short transition cooldown before interacting with that same field again; Google can leave the old field visible while navigation is still in progress.
- CodeBuddy Global human mode is opt-in job metadata: launch visible Camoufox workers with native humanization and use longer transition pauses without weakening consent, region, cancellation, or credential validation gates.
- Bulk import cancellation must immediately finalize active accounts and prevent late browser callbacks from changing cancelled results or saving new credentials.
- Handle corrupt, absent, and legacy data explicitly where the surrounding module supports recovery.
- Under the root Fork Preservation Rule, `oauth/providers.js` stays the WYx0 single-file implementation. Upstream replaced it with a re-export into `oauth/providers/`; adopting that split is a deliberate refactor, never a merge side effect.
- Keep `mergeAccountsAndProxyPoolsFromDb` in `db/index.js` so database imports merge instead of wiping user data.

## Verification

- Run `npm run build` when exports or server bundling change.
